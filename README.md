# Практичне заняття 5. Базовий пайплайн GitHub Actions

Навчальний Node.js-проєкт із CI, який автоматично запускається після кожного
push до гілки `main`.

## Файли проєкту

- `index.js` — виводить `Hello world!`.
- `package.json` — містить команду `npm run build` з початкового завдання.
- `package-lock.json` — фіксує npm-метадані проєкту.
- `.github/workflows/ci.yml` — конфігурація GitHub Actions.
- `.gitignore` — виключає локальні залежності та результат збірки з Git.

## Кроки CI

1. **Checkout repository** — завантаження коду репозиторію.
2. **Set up Node.js** — установлення Node.js 24.
3. **Install dependencies** — виконання `npm install`.
4. **Build project** — виконання `npm run build`.
5. **Verify build** — перевірка наявності непорожнього `dist/index.html`.
6. **Upload build artifact** — збереження папки `dist/` як артефакту `node-build`.

Якщо встановлення, білд або перевірка завершаться з помилкою, завдання CI
буде позначено невдалим. Якщо файли білду відсутні, завантаження артефакту
також завершиться помилкою.

У початковому `package.json` немає зовнішніх залежностей. Команда
`npm install` усе одно виконується в пайплайні відповідно до умови.

## Локальний запуск

Для перегляду повідомлення програми:

```bash
node index.js
```

Для перевірки збірки в Linux або Git Bash із встановленим Node.js:

```bash
npm install
npm run build
```

Початкова команда збірки використовує shell-команди й створює `dist/index.html`.
Для повторного локального білду потрібно спочатку прибрати попередню папку `dist`.
У GitHub Actions кожен запуск отримує чисте середовище Ubuntu.

## Перевірка результату на GitHub

Після push до `main` відкрийте **Actions → Node.js CI → останній запуск**.
Перевірте зелений статус завдання `build`, логи `Install dependencies`
і `Build project`, а також наявність артефакту **node-build** на сторінці запуску.

Репозиторій потрібно створити з видимістю **Public**. На платформу потрібно
подати посилання на цей репозиторій після успішного запуску CI.
